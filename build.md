# Сборка, проверка и публикация

## Сайт: без сборщика

Браузер загружает ES-модули напрямую. Для сайта не нужны npm install, API-ключи или серверная часть. Python 3 нужен только для локального HTTP-сервера, Node.js — для проверки синтаксиса.

Из корня репозитория:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Открыть http://127.0.0.1:8000/. Для проверки прямых переходов открыть /#videos и /#socials. Не открывать index.html через file://: это не эквивалент HTTP-загрузки модулей. Сервер остановить Ctrl+C.

## Проверка перед отправкой

```sh
node --check app.js
node --check content.js
node --check community.js
node --check styles.js
node --check social-styles.js
git diff --check
```

В браузере проверить:
- основной экран, навигацию и прямые якоря;
- воспроизведение ролика до конца, звук, встроенные субтитры и WebVTT;
- кнопку оригинала, точность шести профилей, фокус клавиатуры;
- вёрстку на 320/390 px и широком экране, отсутствие горизонтального переполнения и ошибок консоли.

## Добавление видео

1. Создать пакет по [content-kit](skills/content-kit/SKILL.md) вне публичного checkout.
2. В media/ перенести только проверенные публичные MP4, обложку и WebVTT. Текущий пример: H.264/AAC, 1080×1920, 18 секунд.
3. Обновить community.js: файлы, описание, исходный мем, автор, дата, sourceUrl и расшифровка.
4. Повторить проверку. Изменение сайта само по себе не публикует материал в соцсетях.

Исходный генератор/монтажный сценарий примера в этот репозиторий не входит. Здесь хранятся готовые медиа; новые ролики создаются средствами, доступными в текущей среде.

## GitHub Pages

Pages настроен на корень ветки main; .nojekyll отключает обработку Jekyll. Адрес: https://say2me.github.io/neurochurch/.

Проверить diff и включить в commit только файлы текущей задачи, затем:

```sh
git commit -m "Describe the completed change"
git push origin main
```

Команда commit предполагает, что нужные файлы уже добавлены через git add. Если push не удался, сайт ещё не обновлён. При расхождении веток сначала изучить изменения; не использовать force push.

Для проверки через авторизованный GitHub CLI:

```sh
gh run list --repo say2me/neurochurch --limit 5
gh run watch RUN_ID --repo say2me/neurochurch --exit-status
```

RUN_ID заменить идентификатором сборки своего commit. Дождаться success, затем открыть публичный сайт и проверить изменённый раздел и медиа. Успешный commit локально не считается развёртыванием.

## Скилл из репозитория

Пакет: skills/content-kit/. Установка новой копии в личный каталог Codex из корня checkout:

```sh
python3 - <<'PY'
import os
import shutil
from pathlib import Path

source = Path("skills/content-kit")
destination = Path(os.environ.get("CODEX_HOME", str(Path.home() / ".codex"))) / "skills" / "content-kit"
if destination.exists():
    raise SystemExit(f"Уже существует: {destination}. Сначала сравните версии.")
destination.parent.mkdir(parents=True, exist_ok=True)
shutil.copytree(source, destination)
print(destination)
PY
```

Существующая установка не перезаписывается. Для обновления сначала сравнить локальные правки и заменить только согласованную версию. Вызывать как $content-kit; если обнаружение ещё не обновилось, передать полный путь к установленному SKILL.md.

При наличии системного skill-creator выполнить его scripts/quick_validate.py для папки skills/content-kit. Валидатор требует Python с PyYAML. Дополнительно проверить все относительные ссылки, YAML в agents/openai.yaml и применимость ограничений. Это не проверка качества сгенерированного видео.

## Рабочие данные и расписание

Каталог материалов задаётся параметром `contentDir` в брифе или переменной окружения `NEUROCHURCH_CONTENT_DIR`; это каталог вне публичного репозитория. В текущей установке он уже существует — использовать актуальную конфигурацию задания, а не создавать пустой журнал.

В нём находятся plan-30-days.md, meme-video-policy.md, publication-log.json, community-config.json и пакеты выпусков. При неизвестном каталоге можно подготовить черновик, но нельзя утверждать, что проверены дубли или блокировки.

Публикация выполняется существующим заданием ru-en, ежедневно в 19:00 Europe/Riga, с уже установленными разрешениями. Репозиторий не создаёт и не меняет расписание автоматически. Пароли, cookies, токены, данные регистрации и рабочие журналы сюда не загружаются: корень репозитория обслуживается публичным GitHub Pages.
